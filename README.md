# 轻盘 · 私人智能减脂配餐

中文、浏览器本地保存、无需服务器的个人饮食管理网页。选择真实录入的食物，使用混合整数线性规划自动计算克数。HTML + CSS + JavaScript，无安装依赖，无付费 AI API。

## 本地运行

**最快方式：双击 `index.html`。** Chrome、Edge 等现代浏览器可直接打开。浏览器对 `file://` 本地存储的行为有差异；建议长期使用固定的网址，并定期导出备份。直接打开时也使用独立后台线程计算，支持进度、取消和每方案4.5秒的外部超时终止。请保留 solver-client.js 和 solver-worker-source.js。

推荐安装 Node.js 22 或更新版本，然后在项目文件夹运行：

```powershell
node server.cjs
```

访问 <http://127.0.0.1:4173>。HTTP 下使用 Web Worker 求解，界面保持响应。无需 `npm install`。端口可通过 `PORT` 环境变量修改。本地服务器只绑定本机回环地址，不供手机访问；电脑和手机共同使用时建议部署至 GitHub Pages。

**本地文件、localhost、GitHub Pages 是不同存储来源。** 更换网址、浏览器或设备前先导出 JSON，再到新环境导入。

## 首次使用

1. 首次打开会自动载入系统自带的29种食物。可在「食物库」新增、编辑或删除。数据来自已提供的营养截图及注明来源的参考数据；未知值留空，0表示确定为零。热量与三大营养素需完整；钠可留空，仅在主动开启严格限钠时才要求补齐。
2. 填写实际食用净重，如生肉净重、干面重量或去壳鸡蛋重量，并与营养表的生熟状态保持一致。
3. 到「个人设置」核对目标，保存并应用。初始的1700kcal等只是起始设置，均可修改。可创建多个目标方案。
4. 在「今日配餐」选择食材，填写全天目标热量后直接计算，无需安排早中晚餐。蛋白质、脂肪和碳水沿用当前目标比例，随热量一同调整；可在设置自定义。每条食材可选设重量范围、步长或固定重量。
5. 点击「自动配餐」，比较A/B/C方案，查看差额，必要时调整食物组合与范围。自动重量直接在整数网格上求解，结果还会独立重新核算。
6. 满意后保存套餐。套餐可应用到今天、编辑、复制、重命名、删除。
7. 「记为实际饮食」会复制计划，之后单独调整实际克数。更改计划不会自动更改实际记录。
8. 定期点击「导出完整JSON」。恢复时会先校验备份，确认后替换全部当前数据。

### 克数和营养口径

- 能量支持 kJ，按 `kcal = kJ / 4.184` 转换；内部保留完整精度。
- 统一按 `营养 = 每100g值 × 实际食用净重克数 / 100` 计算，不设置冰衣或可食比例，也不进行二次扣重。旧备份中的比例字段不参与计算。
- 鸡蛋直接按整数个输入或用＋／−增减，自动配餐也按整数个计算。当前每个可食重量暂按50g估算，可在食物库编辑校准。用户实测7个带壳449g仅作记录，不当作去壳重量使用。已有计划保留食物快照，修改每个重量后请移除并重新选用。
- 包装条码为选填的8至14位数字字符串，保留前导零；同一条码不允许重复新增，食物包合并导入也会按条码去重。
- 已确认的两条坚果产品已合并为「纯坚果仁（罐装）」。刷新会合并旧食物库中的重复项，历史套餐及饮食记录的营养快照保留。
- 饮品统一按克。没有密度数据时不默认毫升等于克。
- 钠始终以mg表示，未把食盐当作钠；生重、熟重应分别录入，不自动猜测烹调损耗。
- 油和调味料需自行录入，否则不会被计入全天营养。
- 套餐和历史条目保存食物营养快照。编辑食物库后，已选食物需移除再添加才使用新标签，避免旧记录被改写。

## 目标与自动配餐

### 系统自带食物库与个人修改

`data/foods.json` 是自带食物库的唯一数据源，随网页公开发布。每台新设备首次打开都能直接使用这批食物，无需导入文件。JSON仅包含食物与来源，不包含个人饮食记录或目标。

浏览器首次载入时会把自带食物复制到本地，并在完整备份中保存 `builtinFoodsSeen` 初始化记录。此后编辑不被系统数据覆盖，删除后刷新也不重新出现。系统库增加新编号时仅补充从未初始化过的食物；相同编号的更正不会自动覆盖个人编辑。

「恢复自带食物」只补回缺少的条目，不覆盖已存在的同编号或同名称食物。完整备份恢复尊重备份中的食物选择，不会立刻把刻意删掉的食物补回来。清理浏览器全部数据后会视为新设备重新初始化。

维护自带库时编辑 `data/foods.json`，然后运行 `node build.cjs`。构建会校验JSON并生成 `data/foods.js`，用于兼容双击HTML的离线打开；JS是生成文件，不应单独编辑。部署包含JSON与生成脚本，日常使用无需构建工具或后端。页面中的个人增删改只写本地浏览器，不直接修改GitHub上的JSON文件；手机与电脑各自修改仍需导入导出迁移。

### 仅导入或导出食物

「食物库」新增「导入食物包」和「导出食物库」。食物包格式为 `{ "type": "qingpan-foods", "version": 1, "foods": [...] }`，只合并食物，不替换目标、套餐、计划与实际记录。相同编号或相同名称／品牌／口味／称重口径的条目跳过，不覆盖你已编辑的数据。重复导入不会反复新增。

完整JSON备份仍用于全部数据恢复，导入时会明确提示是否替换。食物包中的缺失营养值仍保持 `null`；默认只要求热量与三大营养素完整，严格限钠时才要求完整钠数据；来源和限制说明在食物库直接显示。不同设备需各自导入，目前没有云同步。

个人照片、个人食物包与备份应放在已忽略的 `.codex-remote-attachments/`、`personal-data/` 或 `backups/`，不要提交到公开仓库。

热量要求在目标的允许百分比内，蛋白质要求不低于目标，脂肪与碳水要求在目标±允许克数内，默认不限制钠，也不因缺钠拦截计算。只有主动勾选「严格限制钠」后，才要求所有所选食物钠数据完整且总钠不超过上限。所有允许差额均可设置。

自动碳水以 `(热量 − 蛋白质×4 − 脂肪×9) / 4` 计算。食物热量仍直接使用录入标签值，不强行把包装热量改成4/9/4折算值。标签有四舍五入，过窄范围可能无解。

- **A**：在硬约束内更重视热量与蛋白质偏差。
- **B**：开启严格限钠时，在硬约束内增加钠含量惩罚；未开启时与A使用同一目标，并在界面明确标注。
- **C**：在硬约束内增加份量区间中点及归一化份量差异惩罚。这是份量均衡，不等于自动保证蔬菜种类、微量营养素或各餐热量均匀。

三种目标可能得到同一解。每条范围必须自己核对，没有适用于所有食物的默认合理份量；初始0–500g只是可编辑范围。想确保所选食物一定出现，请将最小克数设为大于0。固定重量允许非步长倍数，自动重量服从1/5/10g整数步长。

若严格模型未找到解，使用带营养偏差松弛变量的模型提供参考，同时醒目标明未达标和每项差额；份量范围、固定重量、餐次仍遵守。不会把参考结果说成符合目标。单个模型内部限时1.8秒，另有每方案4.5秒的独立线程外部终止保护。默认钠关闭时B直接复用A，仅运行A/C两个任务；所有方案完成前可随时取消。一个方案超时不阻止其他方案返回，默认选中已核验可行方案。没有时限内证明全局最优的承诺；无解与搜索超时会谨慎区分措辞。实现细节见 [算法说明](docs/ALGORITHM.md)。

## GitHub Pages 免费部署

项目仓库：https://github.com/13161324809/qingpan-meal-planner 。包含完整源码、测试和部署工作流。以下步骤用于首次启用或迁移部署。

1. 在 GitHub 创建公开仓库，例如 `qingpan-meal-planner`。GitHub Free 使用 Pages 时选择公开仓库；代码公开，但网页里的个人饮食数据仍只在自己的浏览器中。
2. 将本项目文件上传到仓库根目录，保留 `vendor/` 和 `.github/workflows/pages.yml`。不要上传个人备份、食物记录或任何密钥。
3. 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
4. 推送至 `main`，或在 Actions 手动运行 **Test and deploy GitHub Pages**。
5. 工作流测试通过后只打包静态网页文件到 `dist/` 并部署。到 Pages 或工作流结果查看真实网址，通常为 `https://你的用户名.github.io/qingpan-meal-planner/`。

若使用 Git，可在创建空远程仓库并完成本机 GitHub 登录后运行：

```powershell
git remote add origin https://github.com/你的用户名/qingpan-meal-planner.git
git push -u origin main
```

如果项目尚未初始化 Git，则先 `git init -b main`、`git add .`、`git commit -m "Initial Qingpan meal planner"`。不要重复执行已完成步骤。

也可以选择 **Deploy from a branch → main → /(root)** 直接发布，无需构建；此方式不由上述测试工作流把关。参考 [GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)。

## 开源参考与许可

应用自有代码使用 MIT。实际随附的求解器为 [jsLPSolver 1.0.3](https://github.com/JWally/jsLPSolver)，按其原始 `vendor/LICENSE`（Unlicense）分发。包代码来自固定版本的官方npm分发文件，后续升级应重新运行全部数值测试。

[Mealie](https://github.com/mealie-recipes/mealie) 是参考考察的开源食谱与配餐管理项目；其后端和Vue架构不符合本项目第一版的纯静态要求，因此没有复制其代码或营养数据。仅使用jsLPSolver作为第三方计算实现。

## 范围与限制

已实现MVP及基础每日实际记录、日期历史。未实现体重／腰围趋势、登录、云同步、自动联网获取食物营养。浏览器禁用或清理存储会影响数据持久化；请自行保留JSON备份。更改目标不会未经保存自动执行。无服务器和API订阅成本；第三方托管的免费政策以平台规定为准。

## 本地开发与提交约定

默认只在本地修改、测试和打包。用户明确要求提交、上传或发布后，才执行对应的GitHub写入；本地修改不会自动上传。

后台求解：离线脚本由build.cjs把求解器、core.js及worker入口组合成字符串，file模式使用Blob Worker，无需跨文件importScripts；默认也使用相同的自包含后台脚本；HTTP下未加载该脚本时可使用worker.js。不会退回主线程执行重计算。

### 整体组合套餐

在今日配餐或食物库点击「＋组合套餐」，选择原料并填写一份配方的克数，例如吃鱼料汁。已保存的套餐可在「我的套餐」点击「保存为整体」转换，无需重录。营养按原料用量相加，未知钠仍保留未知。

日常选择后只显示一个整体，默认固定1份，可调整为2份、3份等整数；不接受0.5份，也不会拆开调节原料。自动配餐只调整其他食物。配方保存在食物库，支持编辑、删除和JSON备份；修改配方保留已有计划与记录中的原配方快照。

### 食物价格与费用估算

食物编辑页支持采购总价、规格（g/ml/枚）、成本净重比例和成本密度，也可直接填每100g单价（优先使用）。今日计划、实际饮食、套餐及组合套餐会按实际用量显示费用；缺价或缺换算值会提示只算已知部分，不将未知费用算成真实零。费用使用当前食物库的价格，营养继续使用所选食物快照。

按用户要求，液体费用暂按1ml≈1g粗估，标为估算；黑鱼片采购2500g按95%固体含量折为2375g可用肉重计费，此比例不参与营养计算。鸡蛋按每枚20.99/30元计价。88.8元/5000g对应鸡胸肉片（拼多多）。

香蕉改为带皮称重：每100g带皮重量的热量、蛋白质、脂肪、碳水和钠均以原果肉参考值×65%估算，费用直接按6元/1000g计；不重复扣皮重。原有去皮重量的计划和记录保留原营养快照，费用换算会识别旧称重口径。旧食物库仅在原香蕉参考数值未改动时更新为带皮口径，个人修改保留。

葱、生姜、小米辣营养使用USDA SR28参考：NDB11291、11216、11819；小米辣采用鲜红辣椒通用参考，非特定品种实测值。来源：https://www.ars.usda.gov/ARSUserFiles/80400535/Data/SR/SR28/reports/sr28fg11.pdf
